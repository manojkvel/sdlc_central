# AIDLC hooks

Eight shell hooks enforce the control, evidence and audit rails. Source of truth:
`hooks/<name>/<name>.sh` and `hooks/<name>/hook.yaml`; shared library `hooks/_lib/track-parse.sh`.

## Contract

- **Input:** JSON on stdin: `{event, tool, path | command | prompt, cwd, transcript_path, stop_hook_active}`. Agent adapters convert their native payload (Claude Code: `adapters/claude-code/hooks/wrap.sh`).
- **Exit codes:** `0` allow · `2` block, with `AIDLC BLOCK <hook> <code>: <reason>. Next: <action>` on stderr · `1` hook failure, treated as allow-with-warning.
- **State:** the track root from `track_root` in the agent's `sdlc-central.json` (default `.track`), its `state.md` resume block, and the current phase directory.
- **Inert until adopted:** every hook exits 0 when the project has no `<track root>/state.md`.
- **Logging:** every block appends a row to `<track root>/guardrail-log.md`.
- **Budget:** bash 3.2, `jq` and `shasum` only, no network, under 200 ms.

## Hooks and codes

| Hook | Runs | Codes |
| --- | --- | --- |
| aidlc-pre-write-guard | before a write or edit | W01 no phase · W02 plan not checked / no tier 1 unit.md · W03 gate open · W04 secret target · W05 protected path · W06 stage forbids source writes · W07 decision log written outside the guard · W08 hand-written evidence or scorecard · W09 tier 3 consumer against an unapproved contract |
| aidlc-pre-command-guard | before a shell command | C00 permitted by PLAN.md (allowed, logged) · C01 destructive · C02 destructive while a gate is open · C03 edits hook machinery · C04 writes the decision log · C05 shell write into generated evidence |
| aidlc-artifact-hygiene | after a write under the track root or docs/aidlc | H01 secret · H02 raw context wrapper · H03 TBD/TODO in an approved artifact · H05 evidence not generated by the verifier, or edited after (seal mismatch) (H04, persona manifests, arrives with personas) |
| aidlc-human-approval-guard | on a user prompt while a gate is open | A01 vague approval · A02 wrong gate · A03 required text missing · A04 not exact upper case · A05 authenticated identity required · A06 decider not authorised for the role |
| aidlc-traceability-check | after a write to SPEC, PLAN, TASKS or VERIFICATION; `--phase`, `--all` | T01 orphan REQ · T02 AC/SC unmapped · T03 dangling D/RISK id · T04 untraced task |
| aidlc-artifact-consistency-check | on stop; `--all` | X01 state drift · X02 approved artifact changed · X03 summary contradicts verification · X04 decision without lineage · X05 unknown event family |
| aidlc-phase-quality-gate | called by the quality-gate skill and the runner | Q01 wraps the first failing T/X/H code |
| aidlc-final-verification | on stop (release-ready claim) and before release commands | F01 verification · F02 open review findings · F03 scorecard · F04 stale evidence |

## Decision strings

Exact, upper case, first line of the reply:

```text
APPROVE <GATE>                     e.g. APPROVE SPEC, APPROVE PLAN, APPROVE CENTRAL TDES
APPROVE <GATE>: <text>             required at high / security-sensitive (risk acknowledgement) and release (scope)
APPROVE WORKSTREAM CONTRACT: WS-NNN
APPROVE WORKSTREAM CONTRACT WITH RISK: WS-NNN - <risk and excluded scope>
APPROVE WORKSTREAM PLAN: WS-NNN
LIFT EXCLUSION: WS-NNN
APPROVE WITH RISK: <risk and excluded scope>
REQUEST CHANGES: <reason>
REQUEST VERIFICATION: <missing evidence>
DEFER                              (DEFER RELEASE | REJECT RELEASE at release gates)
```

At low risk a casual reply ("ok", "go ahead") is recorded as `APPROVE <GATE>` with the original text kept.

## Evidence tools

Not hooks, but installed with them (and even with `--no-hooks`): `hooks/_bin/aidlc-evidence.sh` records a run, `hooks/_bin/aidlc-verify.sh` generates the sealed verification artifact. See `docs/aidlc/evidence.md`.
